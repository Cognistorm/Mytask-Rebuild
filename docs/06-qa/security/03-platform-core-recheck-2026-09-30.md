## 3. New findings — Medium

### SEC-49 (Medium) The global limiter keys only by IP: server-side rendering and carrier NAT share one bucket
- **Where:** `apps/api/src/platform/rate-limit/rate-limit.middleware.ts:46` (key = `ipBucket(resolve(req).ip)`, never the user); `apps/web/src/lib/api.ts:6-11` (`serverApi` sends neither `X-MyTask-Visitor-IP` nor `X-MyTask-Service-Auth`); `docker-compose.yml:141-142` (only Caddy is a trusted peer) and `:176` (the web container calls `api:3000` directly).
- **Exploit (in words):** (1) Every server-rendered page calls the API from the web container. Without the visitor headers the API sees the address of the web container for every visitor, so all visitors of the whole site share one bucket of 600 reads per minute. Today only `/health` is fetched server-side and it is exempt, so nothing breaks yet; the first slice that renders data on the server (task lists, profiles) turns this into a site-wide outage that one person can trigger by reloading pages quickly: a few hundred reloads per minute put every visitor into 429. (2) Georgian mobile carriers put many subscribers behind one public IPv4 (carrier-grade NAT). Signed-in users behind the same address share 120 writes per minute, so a busy evening, or one abusive user on the same carrier, blocks honest users (chats, offers, payments) with 429. CONVENTIONS §14 says "per user **or** IP" for exactly this reason.
- **Fix:** key authenticated calls by user id (for example `rl:<kind>:u:<userId>`) and anonymous calls by the IP bucket (read the verified principal from the access token, or move the limiter into a guard/interceptor that runs after authentication); make `serverApi` forward the visitor IP and UA with the service credential (ADR-013 §17) **before** any SSR data fetch, and add a test that two visitor IPs through SSR land in different buckets; product-analyst to confirm whether 120 writes per IP-minute is acceptable behind carrier NAT. **Owner / when:** backend-engineer (limiter) + web-engineer (`serverApi`); before the first slice that reads data during SSR, and in any case before Phase 6.
