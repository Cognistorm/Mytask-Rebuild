## 3. New findings — Medium

### SEC-72 (Medium) `pnpm local`: any web page open in the Owner’s browser can wipe the KYC bucket (or any bucket), because the SeaweedFS master accepts destructive admin requests as a plain GET
- **Where:** `scripts/local.mjs:184-202`. `weed server` runs the master on its default HTTP port 9333 and volume HTTP on 8334, bound to `127.0.0.1`, with no `security.toml`. `docs/SETUP-LOCAL.md:55`: the note only says "never open them in the firewall". Review 06 described the master as "write slots only (orphan blobs)"; that was too narrow.
- **Exploit (in words):** probe P2.
  - The master’s admin API needs no credential and runs actions on a GET. S3 buckets are stored as master collections of the same name.
  - A page the Owner visits while `pnpm local` runs (a malicious ad or a compromised site) only has to load an "image" whose address is the master’s collection-delete URL for `kyc`, `private` or `public-media`. The browser sends the GET, and the bucket’s data is deleted at once; the S3 gateway answers 500 afterwards.
  - The page does not need to read the answer, so CORS does not stop it. Firefox does not block requests from public sites to localhost. Recent Chrome/Edge ask for "local network access", which a user may grant.
  - Today only synthetic data is lost. But the Phase 5 ETL moves real KYC images through this storage (data-model §12), and the attack also breaks every local test session.
  - A local process could do the same; that is accepted, because local processes are trusted.
- **Fix (devops-engineer):**
  1. Do not run the master and volume on fixed, known ports. Let `scripts/local.mjs` pick random free ports for `-master.port` / `-volume.port` on each run, so a web page cannot know the address in advance. The S3 gateway and filer reach them through the internal addresses that `weed server` wires itself. Keep 8333 for S3 only.
  2. Check whether SeaweedFS 4.48 can require a credential for the master admin endpoints (`security.toml`), and use it if it exists. The `[guard] white_list` alone does not help, because the browser’s request also comes from 127.0.0.1.
  3. In SETUP-LOCAL: run the Phase 5 ETL against a stack that is not used for everyday browsing, and back up `.local/data/s3` before the import.
- **When:** before Phase 5 (first real data on this machine). Not a merge gate.

### SEC-73 (Medium) The SEC-64 stop-gap stops working once 500 attached public images exist, because the candidate window never moves past attached files
- **Where:** `apps/api/src/worker/files-scan.sweeper.ts:152-161`. The inner `SELECT` picks the 500 **oldest** ready avatar/portfolio files older than 24 h, **without** the "not attached" condition. The outer `WHERE` then drops the attached ones.
- **Exploit (in words):**
  - Attached images are never deleted, so they stay the oldest candidates forever.
  - Once 500 old attached avatars and portfolio images exist, every run selects the same 500 attached files and deletes nothing. That happens with a few hundred real users, and at once after the Phase 5 import of legacy avatars.
  - Newer unattached uploads are then never reached. Anonymous image hosting under the MyTask media domain (SEC-64) is open again, silently: the run reports 0 and logs nothing.
  - Today, with a handful of local files, it works, which is why the test passes.
- **Fix (backend-engineer):**
  1. Move the three `NOT EXISTS` conditions into the inner `SELECT`, so the 500 are chosen among unattached files only. Keep them in the outer `WHERE` as the compare-and-set.
  2. Loop until a run returns fewer than 500.
  3. Extend the test: more attached old images than the batch size, plus one stray image that must be deleted; and a portfolio thumbnail and a gallery image that must be kept.
- **When:** the next backend pass, before Phase 5 at the latest (together with SEC-74).

## 5. Info
- **I-38 A missing ETag makes the copy unconditional (fail open).** `storage.ts:192` sends `CopySourceIfMatch` only when `read` returned an ETag (`out.ETag ?? null`, `:162`). SeaweedFS, R2 and S3 always return one, so this has no effect today. A provider or proxy that dropped the header would silently remove the SEC-63 protection. Fix: when a scanned upload has no ETag, `copy` refuses instead of copying (reject the file as unreadable and log an error).
- **I-39 Late-quarantine cleanup: Redis is the only record.**
  - If Redis loses the sorted set, re-posted objects under `quarantine/` stay forever (storage cost only; the ETag check does not depend on Redis). That happens without persistence, or with an eviction policy other than `noeviction` in production. Local Redis is `--appendonly yes --maxmemory-policy noeviction` (`local.mjs:160-164`).
  - The same happens for a re-post that starts before the expiry and finishes after the cleanup ran.
  - Each run takes at most 1,000 entries per hour and keeps still-open entries at the front (`files-scan.sweeper.ts:115-133`). Above about 1,000 scans per hour the backlog only grows.
  - Phase 6:
    - add a bucket lifecycle rule that expires `quarantine/` objects after 1–2 days, as the durable backstop (R2 and S3 support prefix rules);
    - require `noeviction` plus persistence for production Redis;
    - let the run loop until no due entry is left.
- **I-40 A 10-minute POST is enough.** The expiry limits when an upload may **start**, not how long the transfer may take: the policy is checked against the request time, and the form fields come before the file part. So a 100 MB file on a slow mobile uplink still completes. I did not probe SeaweedFS with a transfer that crosses the expiry; if a slow-upload test ever fails, check this first. Clients must ask for the form right before uploading; web and mobile do (`createFileUpload` is called after the file is chosen).
- **I-41 The SEC-65 CI step does not prove the forwarding.** `ci.yml:179-181` loads a missing profile through Caddy and expects the localised 404. That page renders the same whether or not `X-MyTask-Client-IP` reaches the web server. The API test proves the bucket split given visitor IPs. To catch a regression in Caddy or `viewerApi`, add one of:
  - a check that the API resolved the SSR call with source `ssr-visitor` (the API request log line in the CI job, or a test-only response header in non-production builds);
  - a web unit test of `viewerApi` with and without the header.
- **I-42 Deleted public variants stay on CDN edges.** Variants are written with `Cache-Control: immutable` (`file-scan.service.ts:253`). Deleting them at the origin (SEC-73 stop-gap, `deleteFile`, avatar replace) does not remove CDN copies. For Phase 6 and the SEC-64 publish design: purge the CDN URLs on delete, or use a shorter edge TTL for user images.
- **I-43 `assertFilerClosed` checks once.** `scripts/local.mjs:254-267` runs right after the S3 port answers. If the filer’s HTTP listener came up later (only possible if the flag were ignored), the check would pass. This is acceptable, since the flag itself is the fix (P1); optionally retry for a few seconds. Cosmetic: the doc comment of `createBuckets` now sits above `assertFilerClosed` (`:252`).
