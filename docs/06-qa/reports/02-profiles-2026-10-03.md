Notes (no action for slice 02 itself; handed to 4.1.27 or 4.1.26b so they are not lost):
- **N-1 (security 4.1.27):** request validation runs before authentication (the global contract validator comes before the guards). A guest learns field errors (400) before getting 401. The schemas are public in `openapi.yaml`, so nothing secret leaks; the security reviewer should confirm that this order is intended (ADR-002 §2 lists the middleware order).
- **N-2 (security 4.1.27):** `createUserReport` counts the SEC-23 limit (`reportLimiter.hit`) **before** it checks the target, so refused attempts (own profile 403, unknown profile 404, blank reason) use up the 10 per hour. This is probably intended (anti-probing), but it is not written down (`profiles.service.ts:288-300`).
- **N-3 (4.1.26b):** AC-16 says "resized to 100 px square for display". The worker keeps the aspect ratio (320/800/1600 `fit: inside`, `file-scan.service.ts:28,231`), and the square comes from `object-fit: cover` on web (`packages/ui/src/web/profile.css:34`) and from the square crop of the app picker (4.1.23b). Part 2 must check a non-square avatar on every screen (web card, header, admin queue, app).
- **N-4 (security 4.1.27):** after `deleteMe` (AC-34) the profile is 404, but the avatar and portfolio WebP variants stay anonymously readable at their unguessable `public-media` URLs (soft delete keeps the files, as legacy did). Personal-data question for the security review and the Owner's privacy policy, not a spec 02 deviation.
- **N-5 (spec 16):** the staff portfolio and KYC queues do not filter out items of deleted accounts. A pending item or verification of a user who deleted their account can still be approved, which queues EV-15 / EV-17 to a deleted account. This is spec 16 queue behaviour; I am recording it here for the slice 16 spec check.
