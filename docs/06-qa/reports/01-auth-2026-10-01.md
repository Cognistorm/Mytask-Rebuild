# QA report: slice 01 — Auth and accounts (spec 01)
Date: 2026-10-01 | QA: ROADMAP 3.15 (independent session; did not write slice 01 code) | Branch: `feat/auth` @ `b7288daa` + the new QA test file
Plan: `docs/06-qa/plans/01-auth.md`. Judged against spec 01 (55 ACs), ADR-002, the slice handoffs and the old platform.

**Status of this report:** complete. Part 1 = 3.15a (automated layer + API-level AC checks, §1–§4); part 2 = 3.15b (screen parity with the live site and `/legacy/`, mobile, i18n, cross-client, emails, §5–§10).

## Verdict: **FAIL** — 1 major, 7 minor (F-01, F-02, BUG-02, BUG-03, BUG-04, F-04, F-05), 0 blockers
The behaviour is right: every one of the 55 ACs has a passing check (API level for all, main flows in the browser on web and admin, cross-client web ↔ app 11/11), and nothing found touches security or money. The slice fails on **parity of the auth screens** (BUG-01, major): the login and register panels on web and app drop the legacy link list (resend verification, privacy policy, terms of service), the legacy subtitle and the "back to home" link, against spec 01 "Screens" ("keep the live structure … and links") and CLAUDE.md ("keep structure, flows and placement"). With BUG-01 fixed (a small change, ROADMAP 3.17) the verdict becomes PASS; QA then re-checks only the screens (§10).

Part 1 interim result (kept for history): no blocker or major bug; minor findings F-01…F-03 and D-1.

## Environment and method
- Windows 11, Node 24, pnpm, Playwright Chromium. Docker is installed but its engine was not running, so the database was PGlite and Redis the in-process stand-in (the same as `pnpm preview`; CI uses real PostgreSQL + Redis).
- Turborepo runs were forced (`--force`, 0 cached) so no result was replayed from the cache.
- Full-stack browser tests ran on a QA copy of `scripts/preview.mjs` with a **fresh database in the session scratchpad** (the seed printed a new Super-admin; the Owner's `apps/api/.pglite` was not touched). The preview starts with S-056 OFF; for the 2FA main flow I switched it ON in that QA database only.
